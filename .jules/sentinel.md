## 2025-02-14 - Fix plaintext password storage
**Vulnerability:** Admin passwords were created and stored in plaintext. They were verified with simple string equality, which is vulnerable to timing attacks.
**Learning:** When migrating plaintext passwords to a hashed format in an existing database, backward compatibility can be maintained by detecting the hash structure. However, this must be done with exact structural checks (`len(string) == 97 and string[32] == "$"`) rather than loose substring checks (`"$" in string`) to avoid false positives where a user's plaintext password just happens to contain the character. Furthermore, timing attacks on sensitive string comparisons (like hashes or plain passwords) should be prevented by always using `secrets.compare_digest`.
**Prevention:** Use `pbkdf2_hmac` or `argon2` for storing passwords securely, and always use constant-time string comparison (`secrets.compare_digest`) when validating sensitive credentials. Implement exact length and character-position constraints when handling legacy fallback checks.

## 2024-10-13 - Secure Password Hashing
**Vulnerability:** The application was storing and comparing the `admin_password` configuration value in plaintext, allowing anyone with database access to view the password, and rendering it vulnerable to basic timing attacks during login comparisons.
**Learning:** Legacy system configurations often default to plaintext storage (`value="changeme"`) for simplicity during bootstrapping, but fail to migrate this securely before deployment. Integrating a backwards-compatible structural check (`len(hashed) == 97` for a PBKDF2 string) in the `verify_password` logic allows for a secure rolling update without locking out existing users, while seamlessly transitioning new passwords into the hashed format.
**Prevention:** Enforce secure password handling from day one by applying hashing mechanisms (`hashlib.pbkdf2_hmac` with dynamic salts) even for default bootstrap credentials. Always use `secrets.compare_digest` for string comparisons on sensitive data to prevent timing attacks.

## 2025-02-18 - [High] Secure Plaintext Admin Passwords
**Vulnerability:** The default admin password ("changeme") was being inserted into the database as raw plaintext upon startup. Furthermore, updates to the password or logging in stored and checked against this plaintext value. This represents a critical data exposure risk if the database is ever compromised, allowing easy unauthorized admin access.
**Learning:** Hardcoded default secrets and plaintext storage for critical authentication systems are severe vulnerabilities. I had to create a dual-strategy implementation to smoothly upgrade security without locking existing administrators out. I added PBKDF2-HMAC-SHA256 hashing for all new passwords and integrated an auto-migration check during the login flow to update old plaintext configurations on the fly when the user supplies a successfully authenticated plaintext credential.
**Prevention:** Never store passwords in plaintext. Always use robust hashing algorithms (like PBKDF2, bcrypt, or Argon2) accompanied by random salts. Furthermore, any sensitive equality checks (like comparing password hashes) must use constant-time operations (e.g., `secrets.compare_digest`) to prevent timing side-channel attacks. Also, ensure type hint syntax matches the established project convention to avoid runtime crashes on older Python versions (e.g. using `Optional[str]` instead of `str | None`).

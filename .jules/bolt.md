## 2024-10-04 - Fix N+1 queries in contexts
**Learning:** In an in-memory SQLite setup (or low-latency DBs), standard latency metrics might not adequately reflect the performance hit of N+1 lazy loading queries. However, they significantly impact database load and memory usage (due to Cartesian products if not careful). SQLAlchemy's `event.listen(engine, 'before_cursor_execute')` allows counting exactly how many queries are executed to measure N+1 reductions accurately. Using `joinedload()` for scalar relationships (like `best_store`) and `selectinload()` for collections (like `deals`, `published_stores`) with chained joins handles this effectively.
**Action:** Always pre-emptively include `joinedload()` or `selectinload()` for related models in Context builders, and measure query counts rather than just latency when optimizing N+1 issues in local development.
